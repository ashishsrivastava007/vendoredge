# VendorEdge R25.2.3 — Normalization Warning Surface

## Purpose
Close the remaining R25.2.2 gap identified during independent review: normalization warnings were correctly computed but were not consumed downstream.

## Changes
- `DecisionAudit` now carries `normalization_warnings` as a bounded, user-visible audit field.
- Any normalization warning forces `evidence_integrity_status` to `UNKNOWN` unless a stronger `CONTRADICTED` state already applies.
- The Decision Evidence UI shows an explicit warning that affected fields were treated as missing rather than guessed.
- R19 Trust Certification now includes a deterministic `normalization_quality` check and reports warnings as `WARN`.
- No raw model prose is exposed through this field; only bounded deterministic warning codes generated by the normalization layer are surfaced.
